Sprint 1:
Throughout the project I have learned quite a bit about different Godot systems. I did some work with polygon2Ds, navigation polygons, tilemap modifying with code, and quite a few other things. It was very difficult to make it so that we couldn't place a tower that would block the path of the troops. I was surprised as to how easy several things I was overcomplicating were after I figured it out. Godot made several things easy that I didn't know about.

Sprint 2:
In this sprint I mostly worked on improving old systems. I also implemented some floating features into the HUD. The two-player system is coming along nicely, and we have a base system that is very easy to grow on. With a little more work I will add in next sprint it will be very easy to add new stuff. But this sprint was mostly cleaning up. I made some code more reusable and fixed some other things. I plan to add keyboard controls over spring break which could be cool.

Sprint 3:
In this sprint I did some cool stuff with territory. I made it so that when we delete a tower, the corresponding territory gets updated. It evens refills any enemy territory that should have taken that space over. You can't take over territory of an enemy anymore. This gets rid of an unfair strat. I also made it so towers could be sold and they work with everything. I put in keybaord controls so we don't need to grab controllers to play. I also did some less notable things that I forgot about. I was surprised at how easy it was to put in keyboard controls. I just had to put in a cursor node with an area2D to interact with the HUD. I think our biggest issue in this sprint was dealing with merge conflicts. We lost quite a bit of time to fixing those issues. I think it all turned out well though. I learned how to resolve them better this time.

Sprint 4:
In this sprint I put in the upgrades for the troops. I made a new class that stores all of the data needed for each troop, and a global script to get the additions. This makes it very easy to upgrade the troops. I am pretty proud of that system. I made it so both players can use the same chunk, making my stuff more reuseable. I have enjoyed making the HUD seperate for both players, but still reuseable. This is a good skill to have. I did have one annoying isue though. I had an error that something couldn't be abstract, even though it wasn't. I fixed the issue by duplicating it and deleting the original. Somettimes coding is stupid. I also implemented the through the time feature to the troops. In the next sprint I need to put in tower upgrades and stuff like that. I'm going to make the 'advance through time' feature a single button for your side. This makes the game board more congruent when everything is the same. I can also use a signal to update things.

Sprint 5:
In this sprint I made the time advancement features for the towers and troops. The towers automatically upgrade when you advance to the next level. I did this by using some cool signals, so everything is congruent. The only thing that doesn't upgrade after placement is the troops, because that wouldn't make that much sense. I implemented a bunch of the sprites that Carson had made so the game looks better now. Some sprites still need to be made, but we are doing good overall. I feel like this was a pretty productive sprint, and we got a good bit of requirements done for submission. The easiest thing we are missing is documentaiton, which I can knock out over the weekend or something. There have been some glitches that were found, so I'll work on fixing those later. The biggest issue was that the towers can shoot your own troops. That one is pretty high priority to fix.
